Part IUnderstanding — read this first

§1What is being measured

The system under test

KC_L is an automated pipeline that writes short explanatory descriptions of knowledge components — the individual concepts in a course, like "Boosting" or "Learning Phase". For each concept the pipeline does two things:

  1. Retrieval — searches the course materials and pulls out the passages it thinks are relevant.
  2. Drafting — hands those passages to a language model, which writes the description.

Both halves can fail, and they fail differently. Retrieval can miss the passage that explains the concept. Or retrieval can find it and the drafter can ignore it. Or the drafter can write something confident that no retrieved passage supports. A good evaluation has to tell these apart.

The ablation: changing one thing at a time

An ablation is the practice of varying exactly one component and holding everything else fixed, so any difference in output can be attributed to that component. We ran two:

FamilyWhat changesWhat is held fixedQuestion answered
IntrinsicThe drafting model — Qwen, Gemma, DeepSeekRetrieval (identical passages)Which model writes better descriptions from the same evidence?
ExtrinsicThe retrieval method — Proposed, DOS-RAG, BaseDenseThe drafter (always Qwen)Which retrieval method finds better evidence?

Each configuration is called an arm. Seven arms × 159 concepts = 1113 descriptions to evaluate. Their short names read as retrieval-drafter: P-Q is Proposed retrieval with Qwen drafting, B-Q is BaseDense with Qwen, and so on.

How the judging works

Grading 1113 descriptions by hand was not feasible, so a large language model does the grading. This is standard practice — LLM-as-a-judge — and it brings its own problems, which is why roughly half this document is about validating the judge rather than about the results.

The judge needs something to grade against. Two different reference points are used, and the difference between them turns out to be the single most important thing in this document:

Graded againstQuestion the judge is askedMetrics
The retrieved passagesIs everything this description asserts actually supported by the evidence it was given?Faithfulness
An expert referenceDoes this description cover what a human expert said the concept requires?Nugget recall, context recall
The short version of what happened

The expert reference was built by editing the Qwen pipeline's own drafts — a deliberate design choice, but one that carries an anchoring risk. That risk has now been audited rather than assumed: an independent reviewer rebuilt references from the corpus with no exposure to any system, and found no distortion and no unsupported content in the library (§10).

The retrieval comparison was nevertheless rebuilt from scratch, because the original metric had a separate and fatal flaw — it compared systems returning 17 passages against systems returning 123, with no rank cutoff (§8.4). The replacement is a standard pooled test collection (§9.1).

§2One KC, traced end to end

Every metric in this document can be understood from a single real example. This is KC_CLF_UND_001 — the concept "Learning Phase" — with real data, not an illustration.

Step 1 — the expert reference

A human expert wrote what a correct description of this concept must contain:

Expert reference · KC_CLF_UND_001 "Learning Phase"gold standard
The learning phase (also referred to as the training phase) is the stage in which a classification algorithm learns from training data. In this phase, the algorithm estimates model parameters, such as the prior probability P(y) and class-conditional probabilities P(x|y), by analyzing the training set. For example, the prior probability P(y) is estimated by computing the fraction of training instances that belong to each class. The learned model is then typically tested over test data to obtain predictive accuracy. This phase is distinct from the querying phase, where the trained model is applied to new data, and from specific algorithmic implementations like Naive Bayes parameter estimation.

Step 2 — break it into nuggets

A nugget is one atomic fact, small enough to be either present or absent with no argument about it. The judge splits the reference into nuggets and labels each one VITAL (leave it out and the description is materially wrong or unusable) or OKAY (true and useful, but elaboration rather than definition).

This happens once per concept and the same nugget list is used for all seven arms — so no arm can be advantaged by getting an easier breakdown.

  • 1vital The learning phase is the stage in which a classification algorithm learns from training data.
  • 2vital In the learning phase, the algorithm estimates model parameters by analyzing the training set.
  • 3okay The prior probability P(y) is estimated by computing the fraction of training instances that belong to each class.
  • 4okay The learned model is then typically tested over test data to obtain predictive accuracy.
  • 5vital The learning phase is distinct from the querying phase, where the trained model is applied to new data.

Five nuggets, three of them vital. Only the vital ones are scored — that is the "strict vital recall" convention from the TREC RAG track [R-04].

Step 3 — grade each arm's description against the nuggets

For each nugget the judge decides whether the description conveys it: SUPPORTED, PARTIAL (gestures at it but omits what makes it substantive), or NOT_SUPPORTED. Wording may differ — the judge is asked about meaning, not phrasing. In the strict score PARTIAL counts as zero.

Step 4 — the arithmetic

Vital-nugget recall on this KC
Qwen 3 of 3 vital nuggets supported = 1.000 DeepSeek 2 of 3 = 0.667 Gemma 1 of 3 = 0.333
In plain terms What fraction of the must-have facts did this description actually convey? That is the whole metric. Averaging it over 151 concepts gives the arm's completeness score.

Step 5 — the other metric: faithfulness

Completeness asks whether the description covered enough. Faithfulness asks the opposite question — whether everything it said is backed by the retrieved evidence. The judge splits the description into individual claims and checks each one against the passages the pipeline retrieved. The reference is not involved at all.

Per-claim faithfulness
supported claims ⁄ total claims
In plain terms Of everything this description asserts, what fraction can be traced back to a passage the system actually retrieved? A description that invents a plausible-sounding sentence loses points here even if the sentence is true.
Now look again at the Qwen draft

Compare it word for word against the expert reference at the top of this section. It is the same text.

That is not a coincidence and not cherry-picking. The expert reference library was built by editing Qwen's drafts, and for this concept the expert accepted Qwen's draft unchanged — as they did for 117 of the 159 concepts. So the nuggets were extracted from Qwen's own writing, and Qwen then scored a perfect 3/3 for reproducing it.

This is the seed problem. §10 quantifies it. Everything in §9 should be read knowing it is coming.

§3Glossary

Every term used in this document, in plain language. Skim it now, return to it as needed.

The system

Knowledge component (KC)
One teachable concept from the course — "Boosting", "Learning Phase". The unit everything is measured on. There are 159.
Retrieval
The search step: given a concept name, pull relevant passages out of the course materials. Three methods are compared — Proposed (ours), DOS-RAG (a strong contemporary method), and BaseDense (a simple dense-vector baseline).
Drafter
The language model that writes the description from the retrieved passages. Three compared: Qwen3.8-27B, Gemma4-31B, DeepSeek-R1-32B.
Arm
One complete configuration — a retrieval method plus a drafter. Named retrieval-drafter: P-Q = Proposed + Qwen.
Ablation
Varying exactly one component while holding the rest fixed, so a difference in results can be attributed to that component.
Abstention
The system declining to write a description at all. Not an error and not missing data — a real behaviour that gets scored. Split into forced (retrieval returned nothing, so declining is correct) and chosen (evidence was available and it declined anyway).

The grading

Judge
The language model doing the grading — Selene-1-Llama-3.3-70B, a model fine-tuned for evaluation. Frozen for the whole campaign: same weights, same settings, same prompts.
Expert reference
A human-written statement of what a correct description of a concept must contain. The gold standard. Critical caveat: ours was created by editing Qwen's output — see §10.
Claim
One assertion extracted from a description. A 200-word description typically yields 8–9 claims. Used for faithfulness.
Nugget
One atomic fact extracted from the reference. Labelled VITAL (definitional — omitting it makes the description materially incomplete) or OKAY (accurate elaboration). 1185 nuggets across 151 concepts, 475 of them vital. Claims come from the description; nuggets come from the reference. Easy to confuse, opposite directions.
Faithfulness
Fraction of a description's claims that the retrieved evidence supports. Answers: is it making things up?
Vital-nugget recall (completeness)
Fraction of the reference's vital nuggets that the description conveys. Answers: did it leave out anything essential?
Context recall
Fraction of vital nuggets that are recoverable from the retrieved passages — judged with no description involved at all. This is what lets us separate a retrieval failure from a drafting failure.
All-or-nothing aggregation
The discarded v1 scoring rule: a description scored 1 only if every claim was supported, else 0. Sounds strict, but it mostly measures length — a longer description has more claims and more chances to fail. See §6.2.

The statistics

Paired comparison
Comparing two arms concept by concept rather than comparing their overall averages. Since every arm describes the same 159 concepts, pairing cancels out the fact that some concepts are simply harder than others.
Bootstrap confidence interval
A way to get error bars without assuming a bell curve: resample the concepts at random 10,000 times, recompute the difference each time, and take the middle 95% of the answers. If that range excludes zero, the difference is unlikely to be noise.
McNemar test
A significance test for paired data. It ignores concepts where both arms did the same and looks only at where they disagreed — if A beats B on 44 concepts and loses on 2, that lopsidedness is what it measures.
Holm correction
Running many tests means some will look significant by luck. Holm tightens the threshold to compensate. We correct within each family of three comparisons.
Macro vs micro averaging
Macro: score each concept, then average the scores — every concept counts equally. Micro: pool all the nuggets together — concepts with more nuggets count more. Our protocol fixes the concept as the unit, so macro governs.
Direct standardisation (length adjustment)
Re-scoring every arm as if all of them wrote descriptions of the same length distribution, so a model can't win just by writing more. Needed because Llama-family judges reward verbosity [R-07].
Pre-registration
Writing down the prediction and the decision threshold, and committing it to git, before running the test — so the analysis cannot be tuned after seeing the answer. Every validation test here was pre-registered.

The problems

Judge qualification
Checking whether the judge's verdicts match a human's. The original gate failed, which is why this document avoids absolute quality claims. That verdict has since been narrowed: scored with the graded completeness metric rather than the discarded binary one, the judge passes all four gates (§8.6). The other three tasks were never disagreement failures — they lack enough minority-class examples to decide.
Second judge / inter-judge agreement
Running an independent model over the same judgements to see whether conclusions depend on the choice of judge. It measures reliability, not validity — two judges can agree and both be wrong (§8.7).
Verbosity bias
The tendency of LLM judges to score longer answers higher at equal quality. Llama-family judges have it strongly; ours is Llama-family.
Serial-position sensitivity
Our own discovery: when the judge is given many passages, it reliably misses information sitting late in the list — even when that information is definitely there. See §8.4.
Seed / anchoring bias
When a gold standard is created by editing a machine's output, it inherits that machine's choices, and grading that machine against it is partly circular. This is what happened to us. See §10.

Why every stage ran one request at a time

Running requests concurrently changed the judge's answers. Under default kernels, concurrency changed 1 verdict in 144. With VLLM_BATCH_INVARIANT=1 — which forces a fixed arithmetic reduction order regardless of batching — it changed 0 of 144 [R-09, R-10]. That flag is not enabled on the machine used for v2, so everything ran sequentially. Slower, but reproducible.

Structured output and blinding

The judge returns JSON constrained by a compiled grammar. Three constraints are load-bearing and were learned by failure: the verdict field must come first (with it last, the model picks its branch by choosing the next key, which made one verdict unreachable — measured as zero occurrences across 36 cases); the rationale must be optional (a required trailing free-text field made the model open a string it had nothing to put in and run to the token cap); and oneOf must be used rather than if/then/else, which compiles cleanly and is then silently dropped from the grammar.

Blinding: arm identity never reaches the judge. 36 forbidden patterns are checked at prompt-build time by a function that raises rather than warns; evidence ids that would reveal the retrieval lane are replaced with opaque SRC_* ids. Exactly one exemption was granted all campaign, for the phrase "a variant proposed by Breiman" in a KC about Boosting — which tripped the guard only because one of our pipelines is named Proposed.

§6Metric formulas

Each with a plain-language reading and its published source.

6.1 Per-claim faithfulness stands

RAGAS faithfulness [R-01]
|{ c ∈ C : label(c) = SUPPORTED }| F(d) = ───────────────────────────────────── |C|
In plain terms Split the description into individual claims; count how many the retrieved passages back up; divide. 1.0 means nothing was asserted that the evidence doesn't support.
C = claims extracted from description d. Abstentions are excluded, not scored zero — a description with no text has no claims, so faithfulness is undefined rather than perfect or failing.

6.2 All-or-nothing aggregation discarded, v1

The v1 rule, and why it was replaced
M1(d) = 1 if every claim is SUPPORTED, else 0 E[M1] ≈ p ⁿ
In plain terms "Perfect or nothing." The problem: if each claim independently has a 96% chance of being supported, a 9-claim description scores 0.96⁹ ≈ 0.69 and a 6-claim one scores 0.96⁶ ≈ 0.78 — so the shorter description "wins" purely for saying less. This is a length measurement wearing a quality measurement's clothes.
The p ⁿ model was fitted on the main corpus and then tested on domain data it had never seen, predicting mathematics' rate to within 0.021 (§9.5).

6.3 Vital-nugget recall withdrawn — §10

Strict vital recall [R-03, R-04]
|{ n ∈ N_v : label(n) = SUPPORTED }| R(d) = ────────────────────────────────────── |N_v| lenient variant: SUPPORTED = 1.0 PARTIAL = 0.5 NOT_SUP. = 0.0
In plain terms Of the must-have facts, how many did the description actually say? PARTIAL counts as zero in the strict score; the lenient half-credit variant was registered in advance as secondary so the choice couldn't be made after seeing results.
N_v = vital nuggets for that concept. Decomposition happens once per concept and is shared by all arms.

6.4 Context recall withdrawn — §8.4 and §10

RAGAS context recall [R-01]
|{ n ∈ N_v : label(n) = PRESENT }| CR(e) = ──────────────────────────────────── |N_v|
In plain terms Ignore the description entirely. Look only at the passages retrieval pulled up, and ask: is the information needed to state each must-have fact actually in there? A low score means retrieval failed and no drafter could have succeeded.
Judged with no drafter in the loop, which is what makes retrieval separable from generation [R-05].

6.5 Aggregation

Macro governs
1 Σ_k s_k M_macro = ─── Σ m_k M_micro = ────────── |K| k∈K Σ_k t_k
In plain terms Macro scores each concept then averages, so all concepts count equally. Micro pools everything, so concepts with more nuggets pull harder. Our protocol makes the concept the unit of analysis, so macro is the one that counts — but both are reported wherever they differ.

§7Statistical methods

Fixed in a pre-registered protocol before the ablation was run.

Paired within-concept difference
1 Δ(a₁,a₂) = ─── Σ [ m(a₁,k) − m(a₂,k) ] |K'| k∈K'
In plain terms Don't compare two arms' averages — compare them concept by concept and average the differences. Some concepts are just harder, and pairing removes that.
K' = concepts where both arms have a defined value. Concepts missing a verdict for either arm are excluded and reported, never imputed.
Concept-clustered bootstrap, B = 10 000
repeat 10 000 times: resample |K'| concepts WITH replacement recompute the mean paired difference CI₉₅ = [ 2.5th percentile , 97.5th percentile ]
In plain terms Error bars without assuming a bell curve. If the middle 95% of those 10,000 answers never crosses zero, the difference is unlikely to be luck. Whole concepts are resampled, not individual rows, because rows from the same concept aren't independent.
Exact McNemar test
b = concepts where a₁ beat a₂ c = concepts where a₂ beat a₁ min(b,c) p = min( 1 , 2 · Σ C(b+c, i) ⁄ 2^(b+c) ) i=0
In plain terms Throw away every concept where the two arms tied and look only at the disagreements. If A wins 44 and loses 2, how surprising is that if they were really equal? Exact rather than approximate because some disagreement counts are small.
Holm–Bonferroni, within family
sort p₍₁₎ ≤ p₍₂₎ ≤ … ≤ p₍m₎ p_adj₍i₎ = max min( 1 , (m − j + 1) · p₍j₎ ) j ≤ i
In plain terms Run enough tests and something will look significant by chance. Holm raises the bar to compensate. With m = 3 comparisons per family, the strongest result must clear a threshold three times stricter.
The two families are corrected separately, as pre-specified. The sensitivity arm is exploratory and enters no confirmatory claim.
Direct standardisation for length
bands B = quintiles of pooled draft length w_b = pooled count in band b ← standard population w_b M_adj(a) = Σ ────── · m̄(a,b) b∈B_a Σ w b∈B_a
In plain terms Sort all descriptions into five length bands. Score each arm within each band, then re-average using the same length mix for everyone. A model that writes twice as much no longer gets credit for that alone.
Renormalising over covered bands prevents penalising an arm with an empty band. Abstentions excluded — a zero-length draft has no band.

§8Validating the judge

Five tests, each pre-registered with a git-verifiable timestamp before its result existed. Two of them changed our conclusions.

8.1 Absolute qualification failed

Does the judge agree with a human? On the only properly-powered task (n=36, 20 PASS / 16 FAIL): raw agreement 0.556 against a required 0.80; Gwet AC1 0.392 against 0.65; PASS recall 0.40 against 0.75. FAIL recall was 1.00 and met its gate.

The failure is one-directional over-flagging — false-pass rate 0.00, false-fail rate 0.60. The judge catches every genuine omission and also flags 12 of 20 descriptions the human thought were fine. Because that strictness is applied to every arm's description of the same concept, it largely cancels under pairing — which is why relative comparisons remain licensed and absolute ones never do.

8.2 Adoption test passed

Registered in advance: the new nugget metric must separate the human's judgements better than the old holistic verdict did, or it is not adopted.

PredictorAUC vs human label
v2 vital-nugget recall0.8578
v1 holistic verdict0.7000

Descriptions the human called complete average 0.650 nugget recall; those called materially incomplete average 0.094. Limit: the test reuses the same 36 single-annotator rows, so it shows v2 is better than v1, not that it is valid in absolute terms.

8.3 Are the two recall prompts on the same scale? yes

Nugget recall and context recall use different prompts, so a systematic difference in strictness would fake a gap between them. Both prompts were shown the same expert reference — from which the nuggets were extracted, so the right answer is 1.0 for both by construction.

Both returned exactly 1.0000 (n=151, 302 calls, offset B = 0.0000, CI [0.0000, 0.0000]). Not a degenerate result — the judge still emitted PARTIALs, and the same scoring path on real data produces wide spread. The registered hypothesis was disconfirmed.

8.4 Does a bigger passage set confuse the judge? yes, severely

Each concept's own reference — which provably contains every nugget — was hidden among unrelated distractor passages at a random position, at three set sizes. The correct answer is 1.0 every time.

The cause is position, not truncation. Within the 123-passage condition every prompt is the same length and only the target's position varies: recall is 1.0000 for positions 0–33 and 0.20–0.40 beyond position 59. Truncation is excluded twice over — a truncated prompt would collapse to exactly 0.0 past a fixed point, yet the last decile still scores 0.3125, and the server allows 40,960 tokens against ~25k-token prompts with every call returning OK. The judge reads the late passages and fails to use them.

Consequence: BaseDense's context recall of 0.4664 sits below the 0.5905 a perfect retriever would score at its set size. Context recall cannot compare arms with different retrieval budgets. No numeric correction is applied — the test's biases run in both directions and cannot be netted out, so the comparison is downgraded rather than adjusted.

8.5 Does the same problem affect faithfulness? no — it reverses

Same manipulation, applied to faithfulness: identical claims judged twice, once against the arm's own ~18 passages and once against those same passages padded to 123.

ConditionFaithfulness

The bias changes sign depending on the question

Padding depresses context recall (−0.41) and inflates faithfulness (+0.02). The explanation that fits both: an overloaded judge falls back on the task's default answer — "not present" when hunting for one specific fact, "supported" when asked whether anything at all backs a claim.

So "long contexts degrade LLM judges" is too crude to act on. The direction depends on the question, and a correction applied with the wrong sign would make things worse.

8.6 Re-running the qualification gate passes

The blanket JUDGE_QUALIFIED = false turned out to be broader than the evidence supported. Reading the original decision task by task, only one task actually failed — the other three returned INSUFFICIENT, which is a sample-size verdict, not a disagreement verdict. TARGET alignment in fact agrees at raw 0.906 (AC1 0.884) and is blocked purely by having 5 minority-class rows instead of 10.

The mechanism, measured

The per-arm deltas differ sevenfold, which is a signal rather than noise. The driver is document length, not passage count: correlation with the MiniCheck score is +0.261 for document words but only +0.053 for number of passages. DOS-RAG retrieves 2,212 words per concept against Proposed's 914, so its claims are more often fully entailed — which strict entailment rewards and a partial-support rubric does not. Our judge rates that gap at +0.016; the independent verifier rates it +0.294, an eighteenfold amplification.

This is a genuine difference of construct, not a defect in either judge.

8.8 The control that makes 8.7 interpretable 0.17% drift

A disagreement between two judges only means something if you know how much the numbers move on a plain re-run. Re-judging with the same judge over re-extracted claims gives exactly that — a full end-to-end repeat of decomposition and judging.

§9What the pipeline does

Three claims, three appropriate statistical forms. Two of them are equivalence claims, which cannot be established by a non-significant difference test — the error the earlier version of this evaluation made.

9.5 A metric that failed negative result

An automated editorial triage — usable as-is / minor edit / major edit / unusable — was run on all 1113 drafts. It fails twice over. It does not discriminate: every arm lands at 97.2–99.3% "usable or minor", and the judge never once used UNUSABLE. And it is not validated: against the expert's own codes on 159 drafts, exact agreement is 0.462 (0.952 within one level), because the judge compresses toward the middle — downgrading 59 of 117 expert-ACCEPT drafts to MINOR_EDIT.

It is reported as a construct failure, not as a result. This is the third metric in the campaign to sit at ceiling and fail to separate arms, alongside correctness and target alignment — a pattern worth reporting in itself: LLM judges asked for holistic editorial verdicts compress toward the middle and do not resolve differences a human resolves.

§10The seed question, settled

The reference library was built by expert editing of Qwen's drafts. That was a deliberate design choice with anti-anchoring controls, but one control — the seed-blind audit — had never been run, so the risk could not be sized. It has now been run.

An independent reviewer, with no exposure to any system output or to the existing library, wrote references for a stratified 30-concept sample directly from the corpus. Comparison was blinded and order-randomised: the judge saw two descriptions as A and B with no indication which was which.

Neither failure mode occurred

The seeded library never disagreed with an independently written reference about what a concept is, and never asserted content the corpus does not support. Those are the two ways a machine-seeded reference could be invalid, and neither appears.

The discriminating test is the stratum check. If the seed had shaped the content, agreement should be worse where the expert accepted the draft unchanged. It is not: accepted concepts agree 13/18, edited ones 5/9 — no effect in the direction seed bias predicts.

Limits, declared before the run. The blind references average 24 words against the library's ~150 and cite about one passage each, so the "missing content" direction is an effort artifact and carries no information about bias — the 9 verdicts in that row were expected. The reviewer also judged all 3 corpus-unsupported concepts to be supported, suggesting a less strict threshold than the original expert. Single reviewer, n = 27. This sizes the threat; it does not eliminate it.

The residual issue that does stand: the nugget set used for completeness inherits Qwen's content selection, so completeness comparisons carry an asymmetry. Completeness is therefore reported as secondary throughout, with that stated.

§11What stands

Supported
  • Retrieval quality and efficiency. Proposed matches DOS-RAG's precision and recall at half the evidence budget and ranks better (nDCG@10 0.5229 vs 0.4074); BaseDense retrieves 7.2× more and ranks far worse (P@10 0.3686 vs 0.6279).
  • Drafter ordering: Gemma ≥ Qwen > DeepSeek, stable across two independent judges and three domains. (The stronger equivalence claim does not survive — see below.)
  • Reproducibility. The pipeline reproduces itself at 99.83% per claim, with no arm moving more than 0.003 across a full re-run.
  • Completeness judging is qualified against the available human labels (§8.6), which narrows the blanket "no absolute claims" caveat.
  • Domain transfer for data-mining and sociology; mathematics is measurably harder.
  • Abstention discipline. Proposed caught 7/7 unsupported concepts; no arm ever drafted from empty evidence.
  • The reference library, cleared by the seed-blind audit on both invalidating failure modes.
  • Every instrument finding — serial-position sensitivity, the task-dependent sign flip, the length artifact, batch-invariance.
Not supported
  • "Proposed retrieves better than DOS-RAG" as a recall claim. They are equivalent on P@10 and R@10. The supportable claim is about ranking and budget.
  • Model-agnosticism as an equivalence claim. Reproduces in only 1 of 3 domains under an independent judge (§8.7). Downgraded to an ordering claim.
  • The groundedness arm ranking beyond its endpoints. Spearman ρ = +0.43 between judges; only "DOS-RAG best, DeepSeek worst" survives.
  • Full domain-agnosticism. Mathematics falls outside the margin for every drafter.
  • Automated editorial triage. Non-discriminating and unvalidated (§9.5).
  • Absolute quality claims outside completeness. M1, M2, TARGET and M4A remain unvalidated for want of minority-class examples — they need roughly 4, 2 and 5 more labelled rows respectively.

§12Threats to validity

Judge qualification partly resolved
Completeness now passes all four gates on the graded metric at a cross-validated threshold (§8.6), bounded by 36 single-annotator labels. The other three tasks are undecided for want of minority-class examples, not because they disagreed.
Judge dependence unresolved
An independent verifier reproduces only the endpoints of the groundedness ranking (ρ = +0.43) and only 1 of 3 equivalence verdicts. Ranking claims beyond the endpoints are not robust to judge choice. The control (§8.8) rules out noise as the explanation.
Seed provenance sized, not eliminated
Control 6 found no distortion and no unsupported assertion, and no stratum effect. But n = 27, one reviewer, and short references. Completeness remains secondary because the nugget set inherits the seed's content selection.
Serial-position sensitivity designed out
Pooled judgements are made one passage at a time, so the failure cannot arise in the retrieval metrics. It still bars the old context-recall figures from use.

§13Paper-ready claims

[C-01] Batch-invariant serving is required for reproducible LLM-judge evaluation
Concurrency changed 1 verdict in 144 under default kernels, 0 of 144 with batch-invariant kernels. Reproducibility is a serving-configuration property, not only a sampling property.
[C-02] All-or-nothing claim aggregation manufactures spurious rankings
The rate is ≈ p ⁿ and therefore a function of length; reproduces out-of-domain to within 0.021.
[C-05] Reference-based metrics are undefined, not merely unmeasured, outside the reference domain
Groundedness transfers because it needs no reference; nugget metrics do not exist without one.
[C-07] Evidence-grounded abstention held across an entire campaign
0 of 1113 descriptions produced from an empty evidence set, across seven arms — and the proposed retrieval caught every corpus-unsupported concept.
[C-08] LLM-judge context recall is serial-position sensitive, so it cannot compare retrieval systems with different top-k strongest
Recall of provably-present content collapses from 1.0000 at 17 passages to 0.5905 at 123, while the same manipulation inflates faithfulness — an overloaded judge falls back on each task's default label, so the bias changes sign by task. The fix is standard and cheap: pooled per-passage judgements, which we then used.
[C-09] Machine-seeded references can be audited rather than assumed methodological
Expert-edited machine output is a legitimate reference-construction method, but the anchoring risk is real and must be sized. A stratified seed-blind reconstruction does it: comparing on substantive relationship rather than lexical overlap, and using the expert's own edit codes as strata, separates "the seed shaped the content" from "the expert edited the weaker drafts". Here it returned zero distortion, zero unsupported assertion, and no stratum effect.
[C-10] Model-agnosticism is an equivalence claim and needs equivalence statistics methodological
A non-significant difference test is not evidence that a pipeline is model-agnostic — it is equally consistent with low power. TOST against a pre-registered margin, plus a variance decomposition reporting the drafter's share of quality variance, states the property quantitatively and degrades gracefully when it holds only within a capability band. Here: 0–6.4% for drafters of comparable capability, against 15.5–39.5% including a weaker one.
[C-12] A judge that fails on a binary rubric can pass on a graded one methodological
The same judge, the same labels, the same rows: 0.556 raw agreement as a binary verdict, 0.8611 as a graded score thresholded leave-one-out. The failure was one-directional over-flagging, and a uniformly strict judge with graded output can be calibrated where a binary one cannot. Before concluding an LLM judge is unusable, check whether the rubric rather than the judge is discarding the information.
[C-13] Inter-judge reliability must be measured against a re-run baseline methodological
Two judges disagreeing means nothing without knowing how much a plain re-run moves the numbers. Here the same pipeline reproduces itself at 99.83% per claim (ρ = +0.96) while two independent judges reach only 0.72 (ρ = +0.43) — which establishes the disagreement as construct difference rather than noise. Reporting the second judge without this control would have been uninterpretable. The mechanism was then identified by measurement: strict entailment rewards longer retrieved evidence (r = +0.26 with document words) where a partial-support rubric does not.
[C-11] Holistic editorial verdicts from an LLM judge do not resolve what a human resolves negative result
An automated post-editing triage placed 97–99% of every arm's drafts in the top two categories and never used the bottom one, agreeing with expert codes only 0.462 exactly. Third metric in this campaign to fail this way.

[C-03], [C-04] and [C-06] concerned the earlier reference-mediated metrics and are superseded; they remain in the findings log with their status changed rather than deleted.

§14Reproducibility

Every result regenerates from committed JSONL. The consistency audit re-derives each property from raw data rather than trusting the report and exits non-zero on failure.

Reproducibility, measured. A full end-to-end re-run of decomposition and judging agrees with the original on 99.83% of 7,610 claims, with support-rate drift of −0.0001 and no arm moving by more than 0.0027 (ordering ρ = +0.9643). Batch invariance is off on this server and 1.5% of drafts re-decompose to a different claim count, but it barely propagates to aggregate conclusions.

Judgement volume across the campaign: 1113 ablation rows × 4 stages, 604 evidence-configuration judgements, 302 calibration calls, 453 dilution calls, 435 faithfulness-dilution calls, 1137 crossed groundedness rows, 8246 pooled relevance judgements, 1113 triage judgements, and 30 seed-audit comparisons, 2,250 claim extractions, 2,083 re-judgements over stored claims, and 15,661 independent verifier scores — with zero unresolved call failures in the v3 stages.

Re-deriving rather than trusting caught five real defects: a micro/macro aggregation inconsistency, a coverage misstatement, a misleadingly-named field, an over-claimed seed-bias conclusion, and — in the seed audit itself — an inverted de-blinding map that had reported the opposite conclusion. That last one was caught by reading the output rather than accepting it, and was recoverable only because both the raw label and the blinding flag were stored.
