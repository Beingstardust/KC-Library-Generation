# 57. INT-15: one payload branch of three did nothing when the reranker got there first

D3 in doc 50 was "lead-in admitted without its payload". INT-11 fixed the instances where the
payload existed in another extractor's rendering. This is what was left after that, and it turned
out not to be a retrieval-quality problem at all.

## Accounting for every admitted promise

`_int15/diag_d3_lead_in.py` walks every packet, finds every admitted passage that
`ends_with_lead_in()` accepts, and reports what happened to the block after it. The corpus is read
the way `02_build_kc_packets.py` reads it, INT-11 repairs applied first, so the counts describe the
pipeline as it now runs.

```
     85  payload already admitted
     55  successor rejected: not formula-shaped
     26  no successor block
     25  successor rejected: still-damaged rendering (INT-11 found no twin)
      5  payload is a formula but was NOT admitted
```

Four of those five rows are the right answer:

- **not formula-shaped (55)** is mostly a colon introducing prose, a table header row, or a
  bulleted list. `is_formula_payload` is correct to decline them.
- **still-damaged (25)** is a payload whose only rendering is destroyed and which INT-11 found no
  intact twin for. Admitting it would put a destroyed formula in a packet.
- **no successor (26)** is examined below; the refusal is correct.
- **already admitted (85)** is the rescue working.

The last row is a bug.

## The bug: three branches, one of them different

`assemble_passages` has three payload branches. `structured_list_payload` and
`procedure_list_payload` both end the same way:

```python
payload_entry = best.get(payload_key)
if payload_entry is None:
    best[payload_key] = {...}
else:
    payload_entry["structured_list_payload"] = True
    payload_entry["ownership_context_text"] = tail_text
```

`lead_in_payload` was guarded by `if nxt and nxt not in best:` and had no `else` at all. If the
reranker had already surfaced the payload on its own weak score, the branch did nothing. The
payload then kept an ordinary `cross_encoder_relevance` basis, which meant it was re-tested by the
severed-fragment, structural-junk and rival-claim filters that payload admission exists to exempt
it from, and it sorted on raw relevance behind ordinary prose rather than first.

So the rescue's effect depended on an accident: whether the reranker happened to also find the
payload. Finding it made the outcome *worse*.

`_int15/diag_d3_why.py` reads that off the packets. Of the five:

```
[Gain Ratio]          payload absent entirely     27 passages,  5183 chars
[Laplace Estimator]   payload dropped to a rival   5 passages,  1568 chars
[Random Forest]       payload absent entirely     40 passages, 10263 chars
[ROC Curve]           payload absent entirely     28 passages, 12331 chars
[ROC Space]           payload absent entirely     40 passages,  8738 chars
```

Laplace Estimator is the unambiguous one: its payload is recorded in its own unit's
`evidence_dropped_to_rival_units`, which is only reachable by a passage that was scored, which is
only true of a passage that never got the rescue basis. Two of the others sit at exactly the
40-passage cap, which rescue-basis passages are seated ahead of.

## The fix

Make the branch do what its two siblings already do. No new policy: `ends_with_lead_in` is still
the trigger, `is_formula_payload` is still the gate, and promotion sets the flag without touching
relevance, exactly as the siblings do.

## Guards, and two that passed for the wrong reason

Eight checks, INT15-1 to INT15-8, run against the real `assemble_passages` over a two-block
synthetic document. Two of them were wrong when first written and sabotage said so.

**INT15-7** asserted no branch still guards on membership of `best`, by substring. It failed on
the correct code, because the comment documenting the old guard contains the words it searched
for. This is the second time in this audit a guard was defeated by a comment about the thing it
was checking; INT13-3 was the first. Rewritten to read the syntax tree.

**INT15-6** asserted a promoted payload survives the rival-claim drop, using a fixture holding
only the payload. `drop_passages_claimed_by_rivals` keeps at least `MIN_KEEP` passages whatever
the scores say, so the fixture was kept by that floor and the guard proved nothing: removing the
promotion left it passing. The payload now competes alongside three passages no rival claims, and
INT15-6b asserts the same payload on an ordinary basis *is* dropped, so the pair brackets the
behaviour from both sides.

Seven sabotages, all caught by their target guard, tree restored byte-exact, suite green before
and after.

## Rejected: recovering a successor from page geometry

The 26 promises with no successor are all blocked by one rule: `build_block_successor_index`
refuses adjacency on either side of a reused extractor block ID. Block IDs here are
`doc:extractor:page:index`, so a reused one means the extractor emitted two different blocks under
the same page and index. Every reused ID in the corpus comes from `mineru`: 804 of 45,596 IDs
(1.76%), covering 1,905 blocks.

Geometry looked promising. Each row carries a page and a bbox, and 797 of the 804 collisions are
separable by page and position. `_int15/diag_geometric_successor.py` therefore tested a strict
rule: same page, starts below the pointer's bottom edge, same column within 24 points, nearest
such block, unambiguous.

It recovers 4 payloads. It is also wrong:

```
geometry vs the extractor's own ordering, where both exist:
  agree       : 24
  DISAGREE    : 101
  unmeasurable: 45
```

Geometry contradicts the extractor's own reading order in 101 of 125 measurable cases. A rule that
disagrees with the known answer four times out of five cannot be trusted where the answer is
unknown. One of its four "recoveries" shows what that costs: Ensemble Classifier's promise, "the
ensemble of classifiers can be constructed in many ways:", resolves to a Naive Bayes m-estimate
formula. That is the D2 misattribution failure, manufactured on purpose.

Rejected on measurement. The existing refusal is correct, and the 26 stay unfilled.
