# 63. INT-18 and INT-19: provenance, and whether the draft is about the unit

Two small additions from the external review of r3. Both are reporting, neither changes what is
retrieved or drafted.

# INT-18: which documents, not only how many

The review's section 6 observed that some units are supported by `DOC_Guides_merged` rather than
the three textbooks, and that this matters for a claim of the form "grounded in the course source
corpus". It named three: Spearman Rank Correlation, Directly Density-Reachable, Density-Reachable.

The packet reported `distinct_documents` (a count) and not which. So the reviewer had to open every
packet by hand to check a claim about the sources.

## Measurement

`_ownership/prov.py` over the r2 packets:

```
evidence rows per document
   1290  DOC_introduction_to_data_mining
    960  DOC_Guides_merged
    217  DOC_data_preprocessing_book_Chapter_3n4
    137  DOC_data_preprocessing_book_Chapter_7

units whose admitted evidence comes from ONE document only: 27
     20  DOC_introduction_to_data_mining
      3  DOC_Guides_merged
      3  DOC_data_preprocessing_book_Chapter_3n4
      1  DOC_data_preprocessing_book_Chapter_7
```

The three units resting solely on the guide document are:

```
Directly Density-Reachable   grounded   {DOC_Guides_merged: 12}
Density-Reachable            grounded   {DOC_Guides_merged: 11}
Spearman Rank Correlation    grounded   {DOC_Guides_merged: 8}
```

**Exactly the review's three.** 3 of 3, with no false positives among the other 156. That is the
cleanest correspondence anything in this audit has produced, and it is not a coincidence: "I could
not find this in the textbooks" and "all its evidence came from one non-textbook document" are the
same fact observed from two directions.

## The change

Two additive fields on `coverage_summary`:

```python
"evidence_by_document": {doc_id: count, ...},
"single_document_evidence": bool,
```

Deliberately **not** a quality signal. A single-document unit can be perfectly correct, and which
documents count as authoritative is a decision for whoever owns the corpus, not for this module.
INT18-5 asserts the field never reaches the packet builder's admission logic, because the moment a
provenance fact gates admission it stops being a neutral fact.

Five guards, four sabotages, all caught.

# INT-19: the definitional sentence has to be about the unit

The review's most serious finding is Mutually Exclusive Classes, whose draft says:

> In the context of rule-based classification, a rule set is defined as mutually exclusive if no
> two rules within the set are triggered by the same instance.

True, well-evidenced, and about **rule sets**. The unit is about classes.

Nothing in the pipeline checked this. Every existing check asks whether the draft is faithful to
its evidence. Faithfulness and relevance are different properties, and a packet full of correctly
retrieved evidence about a neighbouring concept produces a draft that passes every faithfulness
check ever written.

## The rule

Match a definitional sentence in the first three sentences, take its subject, and compare it with
the unit's own name by prefix-stemmed content words. Flag when they share nothing.

## Three false positives that shaped it

The first version flagged 10 of 159, and reading them showed the check was mostly measuring its
own defects:

- `(?:A|An|The)?` without a word boundary ate the subject's first letter, so Accuracy was reported
  as defining "ccuracy" and Irrelevant Features as defining "n attribute".
- A fixed suffix list stemmed "Density-reachability" and "Density-Reachable" apart, and
  "duplicates" and "Duplicate" apart in the other direction.
- Hyphenated names were compared as single tokens.

Fixing those took it to 5 of 159. Prefix comparison at six characters replaced the suffix list:
cruder, needs no list and no linguistics, and for deciding whether two words are the same term it
is simply more reliable. Each of the three defects is now a negative guard, INT19-3 to INT19-5, so
the check cannot regress into measuring itself again.

## What it flags on r3

```
Mutually Exclusive Classes            defines "rule set"
Cluster Definition                    defines "Sometimes a threshold"
External Index: Rand Index / Jaccard  defines "They"
Redundant Features                    defines "common example"
Irrelevant Features                   defines "attribute"
```

Four are defensible on reading: one defines a neighbouring concept, one opens on a peripheral
sentence, one opens with an unresolved pronoun, one opens with an example instead of a definition.
The fifth, Irrelevant Features, is borderline - "An attribute is defined as irrelevant if it is
not useful for the classification task" is a reasonable definition phrased subject-first.

5 of 159 with roughly one borderline is a precision a reviewer can live with. That is the standard
the INT-12 header sets and it is the right one: a hygiene check that fires on ordinary prose
teaches a reviewer to ignore the sidecar, which is worse than not having the check.

Eight guards, six sabotages. INT19-7 asserts the check is actually called, because a flag-only
check nothing invokes is INT-13's defect repeated; INT19-8 asserts the sidecar still never
rewrites a draft.
