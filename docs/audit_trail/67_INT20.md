# 67. INT-20: the defining-equation rescue could not read its own corpus

Found by refusing to accept a regression at face value. Precision and Rand Index appeared to lose
their defining formulas in the r5 packets, which looked like damage from INT-15 or INT-16.

## Working through it

Each hypothesis was checkable, and each one was checked rather than assumed:

| hypothesis | test | result |
|---|---|---|
| INT-15/16 caused it | the INT-15 A/B "before" arm, code-identical to r4 | also lacks them |
| the dense cache is lossy | read the cache path in `DenseIndex` | `np.savez` is lossless for float32 |
| hardware | A100 build vs A30 build, identical inputs | 1 unit, 1 non-formula row |
| lost an ownership contest | `evidence_dropped_to_rival_units` | not recorded there |

Nothing left but a floor. And `Precision = TP/(TP+FP)` begins with the unit's own name, which is
exactly what `name_anchored_defining_equation` and its lower floor (0.45 against the ordinary 0.55)
exist for. So the question became why that rescue was not claiming it.

## The defect

```
(?<![A-Za-z0-9])Precision\s*(?:\([^)]{0,30}\))?\s*=(?!=|>)

match=False   $$ P r e c i s i o n = \frac { T P } { T P + F P } $$
match=True    $$ Precision = \frac { T P } { T P + F P } $$
```

The extractors render display math one character at a time. **582 of 4,649 equation-shaped corpus
texts** are letter-spaced. A pattern built from a unit's name cannot match its own equation in any
of them, so the rescue was dead for the entire category.

That is the INT-13 defect class - a mechanism that exists and never fires - found for the third
time in this audit, after the status-integrity gate and the two content repairs.

## The fix, and why collapsing is safe here and nowhere else

`is_defining_equation` tries the raw text first and, only if that fails, a copy with letter-spacing
collapsed. A run of at least three single letters separated by single spaces is one word.

The safety argument is narrow and it is the whole justification: **the collapsed text still has to
match THIS unit's own name.** A wrong join cannot admit a foreign unit's formula; it can only fail
to match. INT20-2 asserts it directly by testing Recall's letter-spaced formula against Precision's
pattern and requiring False. INT20-7 pins the collapse to exactly two occurrences in the module -
one definition, one call site - because a second caller would inherit an assumption that is only
true where the result must match the unit's own name.

Precision's **0.560** against a 0.55 floor is the point of the whole investigation: that formula
was never reliably admitted. It sat 0.01 above the floor and fell below it whenever anything
perturbed the score, which is why it looked like a regression caused by an intervention.
Specificity's **0.374** could never clear the ordinary floor at all and is admissible only through
the defining-equation floor - it was not borderline, it was unreachable.

## What it does not do

Stated because the temptation is to report the win and stop.

**Accuracy** gains a worked numeric example, not the symbolic
`Accuracy = (TP+TN)/(TP+TN+FP+FN)`. **Rand Index**, one of the two units that started this
investigation, is not recovered at all: its rendering wraps the name as
`{ \mathrm { R a n d I n d e x } }`, and collapsing letter-spacing leaves `{ \mathrm { RandIndex } }`,
which still does not match `Rand\s+Index\s*=`. Predicted before the A/B ran, and confirmed by it.

Handling the `\mathrm{}` wrapper is a separate change needing its own precision measurement. It is
not attempted here.

## Guards and sabotage

Seven guards. INT20-1/3 assert both renderings are recognised; INT20-2 is the safety property;
INT20-4/5/6 pin the collapse's behaviour on a letter-spaced word, on ordinary prose, and on text
with no spacing to collapse; INT20-7 pins the single call site.

Four sabotages, all caught by their target guard, tree restored byte-exact, suite green before and
after. Suite 456 -> 463 checks.
