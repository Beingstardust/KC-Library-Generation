# 60. INT-16: a formula is admitted with the sentence that says what its symbols mean

Three r3 drafts state a formula and then report that its symbols are undefined:

> The precision of cluster i with respect to class j is defined by the relation
> precision(i,j)=pij. ... The source material does not provide a further expansion of the symbol
> pij.

> The recall of cluster i with respect to class j is defined by the formula recall(i,j) = m_ij /
> m_j ... The symbol m_ij is not explicitly defined in the provided source passages.

> The formula for entropy is given as Entropy(D) = ... The evidence does not define the symbols
> p+, p−, c, or pi(t).

The drafter is being honest. The glossary really was not in the packet.

## Why not

`assemble_passages` had three rescues that admit a block because the source structure binds it to
an admitted neighbour: `lead_in_payload` (the block after a promise), `structured_list_payload`
and `procedure_list_payload`. All three look **forward from a pointer**. Nothing looked forward
from a **formula**, and in these documents a formula's symbol glossary is the block immediately
after it, opening "where".

## Measurement

`_int16/diag_where_clause.py`, over every admitted formula in the r2 packets, using the shipped
predicate itself so the measurement and the rule cannot drift apart:

```
    513  successor is not a qualifier the rule accepts
      9  formula has no successor block
      7  qualifier LEFT BEHIND
      3  qualifier ALREADY admitted
```

Seven units: Information Gain, Precision, Significance Level (alpha), Redundant Attributes,
Pearson Product-Moment Correlation, Covariance, Information Gain (Feature Goodness). Example:

```
formula  : $$ I G ( A ) = I ( D ) - \sum _ { j = 1 } ^ { p } \frac { | D _ { j } | } { | D | } ...
qualifier: where $| D |$ is the number of instances in D, and $P _ { D } ( c _ { i } )$ are the
           prior probabilities for data D.
```

Note which units these are **not**: External Index Precision, Recall and Entropy, the three that
prompted the work. For those the definition of `p_ij` sits elsewhere in the corpus entirely, not
adjacent to the formula, so adjacency cannot reach it. Two different problems with one symptom,
and this fixes one of them. Said plainly here so the next reader does not expect those three to
improve.

## The rule

```python
_QUALIFIER_OPENING_RE = re.compile(r"^\s*(?:where|in which|here,)\b", re.IGNORECASE)


def defines_the_symbols_above(text: str) -> bool:
    """True for a glossary block belonging to the formula immediately before it."""
    raw = str(text or "").strip()
    if not raw or len(raw) > _PAYLOAD_MAX_CHARS:
        return False
    if not _QUALIFIER_OPENING_RE.match(raw):
        return False
    return has_mathematics(raw)
```

The mirror of `_LEAD_IN_RE`: that recognises a promise whose payload follows, this recognises a
gloss whose formula precedes. Three gates, all structural: the anchor must be a formula, the
successor must open with the word, and it must actually mention symbols. The branch promotes an
entry already in `best` rather than skipping it, which is INT-15's lesson applied from the start.

## The refactor that came with it

Adding a fourth payload branch by hand would have meant editing four separate sites that each
enumerated the three existing flags:

```python
if not (entry.get("lead_in_payload") or entry.get("structured_list_payload")
        or entry.get("procedure_list_payload")):
```

That duplication is precisely what caused INT-15: one of three branches behaved differently from
its siblings for as long as nobody compared them. So membership is now stated once,

```python
PAYLOAD_ADMISSION_FLAGS = (
    "lead_in_payload", "structured_list_payload", "procedure_list_payload",
    "formula_qualifier_payload",
)


def payload_basis(entry):
    for flag in PAYLOAD_ADMISSION_FLAGS:
        if entry.get(flag):
            return flag
    return None


POINTER_PAYLOAD_ADMISSION_BASES = frozenset(PAYLOAD_ADMISSION_FLAGS)
RESCUE_ADMISSION_BASES = POINTER_PAYLOAD_ADMISSION_BASES | {"name_anchored_defining_equation"}
```

and every site reads it. INT15-8 was rewritten to iterate the tuple as well, so it covers a branch
added later without anyone remembering to edit the guard.

## Guards

Ten, INT16-1 to INT16-10, run against the real `assemble_passages` over a two-block document.
INT16-1/2 assert admission when the reranker missed the glossary and when it did not; INT16-3/4/5
assert each gate still gates; INT16-6/7 bracket the rival-drop exemption from both sides, using
the three-filler fixture that INT15-6's sabotage taught was necessary; INT16-8/9/10 assert the
tuple property and that no site enumerates the flags by hand again.

The first version of INT16-1 and INT16-2 **failed against correct code**. The fixture glossary was
"where |D| is the number of instances in D and p_i is the prior probability", which `has_mathematics`
returns False for: without `$` delimiters it carries no symbol the corpus recognises. The fixture
was wrong, not the rule, and it was fixed rather than the gate loosened to accommodate it.

That failure is worth keeping in mind: **a plain-text glossary is not accepted by this rule.** The
earlier form of the measurement counted 12 such successors ("qualifier carries no symbols"). Those
are real glossaries the rule declines. Widening `has_mathematics` to reach them is a separate
change needing its own precision measurement, and was not attempted here.
