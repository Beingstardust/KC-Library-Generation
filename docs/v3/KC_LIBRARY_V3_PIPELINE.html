The Step 5p dependency, and how it was removed

Until 944db97 the data-mining runs read profile rows from a Step 5p output file. Only registry-derived fields were consumed, but the file itself was a profiling artifact — so the independence claim was not literally true for that domain. Profiles are now derived from the hierarchy alone.

Verified field-by-field rather than asserted: of the six fields retrieval reads, five are byte-identical between the old and new source. The sixth, parent_topic_label, differed on all 159 units — and the 5p file was wrong, recording each KC's parent as itself.

That error had a silent cost. Sibling grouping keys off the parent label, so sibling_kc_names was empty on 159 / 159 packets, disabling three anti-contamination instructions in the drafting prompt. Correct parents produce 23 sibling groups, mean size 6.9, none empty.

Stages

Data flows in one direction. Each stage below states what it does, and how.

00

Profile derivation

What. Turns the KC registry into one profile row per knowledge unit.

How. Walks hierarchy_overlay.jsonl; every node carrying a kc_id becomes a unit. Five fields are copied verbatim (id, type, label, parent label, path); the sixth, deterministic_label_variants, is a pure string function — hyphen and slash normalisation, parenthetical stripping, generic-suffix stripping. No model is invoked, and none ever has been for this file.

01

Query formulation

What. Produces the candidate query forms that will be tried for a unit.

How. Two forms at most, and both denote only the unit: its canonical name, and the same name with an acronym expanded against an ancestor label whose initials match it (NB Learning Phase → Naive Bayes Learning Phase). An ancestor label is never appended as free context — measured on real data, Unit (Category) made the reranker score passages about the category at 0.70+, which is how a unit gained 15 passages while losing its definition and its formula.

02

Recall — three channels

What. Gathers a wide candidate pool from the corpus.

How. BM25 over all sentences, built from scratch on sparse matrices. Pseudo-relevance feedback takes the top-ranked sentences for the base query and pulls their most distinctive terms back into it, so the corpus supplies its own vocabulary bridge — this replaced the LLM-authored aliases. Dense retrieval adds semantic neighbours a lexical method cannot reach; its embedding matrix is cached on disk, keyed by corpus path, size, mtime and model, so a changed corpus misses rather than silently reusing stale vectors.

03

Precision — cross-encoder ranking

What. Scores every candidate against the unit's own query text.

How. A local cross-encoder scores each (query, sentence) pair; the logit passes through a sigmoid so 0.5 is its own relevant / not-relevant boundary. This is the sole admission authority — a candidate's channel of origin buys it nothing.

cls CrossEncoderRerankermodel bge-reranker-v2-m3
04

Admission and assembly

What. Decides what enters the packet, and assembles sentences into coherent passages.

How. A sentence must clear the floors below and survive the structural filters. Surviving seeds are expanded to their whole source block, deduplicated across extractor variants, then the assembled text is re-scored — because what reaches the drafting model is the block, not the sentence that matched it.

fn assemble_passagescaps 40 passages / 14 000 chars
05

Query selection

What. Chooses which query form the unit is actually best expressed by.

How. Every candidate form is run through the same full retrieval it would receive, and the winner's work is kept — no cheap probe, because selecting on a smaller sample than the decision governs proved unsound (it ranked one unit's forms backwards and cost it 35 passages). Forms are ranked by definition/formula/procedure coverage first, then mean relevance, then volume — so a vague query cannot win by admitting more merely-acceptable material.

metric core shapes → mean relevance → count
06

Packet emission

What. Writes one drafting packet per KC, and one per topic.

How. A KC packet carries its evidence, shape coverage, sibling names, hierarchy path and the query-selection record. Topic packets are built from the same evidence that grounds their child units — not from the children's finished drafts, as the original pipeline did. That removes a sequential dependency and, more importantly, stops errors in a child draft propagating upward unchecked. Passages are taken round-robin across children so one verbose child cannot crowd out its siblings.

Drafting

What. Writes the KC and topic drafts as structured JSON.

How. The one generative step. Before serialisation the packet is copied and source-document pointers are neutralised — Figure 3.7 becomes the figure, bracket citations are dropped — so the model cannot copy a number it never sees. The stored packet keeps verbatim text, so provenance and downstream grounding checks are unaffected. All four prompt paths neutralise, including both repair prompts.

Structural filters

  • Citation density — two or more bracket citations is a survey listing; a single citation attached to substantive text is ordinary academic writing and is kept. The narrower rule was measured: the strict version discarded 2 025 sentences, including 162 definitions and 21 formulas.
  • Bibliography entries — venue, page-range or volume markers co-occurring with a year. Flags 0.70 % of the corpus, zero of it formula-shaped.
  • Document-structure noise — table-of-contents rows and pointer-only text. A cross-reference inside real content is kept; only text that says nothing once its markers are removed is dropped.
  • Garbled-math penalty — de-prioritises OCR corruption so a clean rendering of the same equation wins.
  • Boilerplate override — a is_nav_boilerplate / is_meta flag does not outrank visible equation form. The overlay mislabels some formulas as navigation; of 3 960 flagged sentences only 92 are equations, and those are real.

Why the fix-liveness harness exists

Four fixes in this project were present, committed, and doing nothing. Each was found by accident, not by test:

  • A regex lost its word boundary passing through a shell heredoc and matched nothing, while the tests it fed still reported progress.
  • admission_basis was computed but never stored, so every lookup depending on it saw None.
  • A defining-equation floor could never fire, because a length filter discarded the passages before any floor applied.
  • sibling_kc_names was empty on all 159 packets — silently disabling three anti-contamination instructions — while a source comment asserted it was populated.

verify_pipeline_fixes.py runs 21 checks, each executing the real code path and asserting on observed behaviour rather than the presence of source text. A fix that exists but does nothing fails. It runs before every build, and it immediately caught a fifth: pointer neutralisation had been applied to the two drafting prompts but not to either repair prompt — so any draft that failed validation was retried against a packet still containing Table 4.4 and [79].

Domain portability

Nothing in the pipeline encodes subject matter. Verified two ways rather than claimed: the project's own domain-agnosticity test passes, and the same code was run end-to-end on a sociology corpus and hierarchy it had never seen — 24 005 sentences, 97 units, profiles built from the hierarchy with no profiling model in the path.

Known limits

  • Corpus gaps are real. McNemar, Nemenyi and Friedman have no definitional content in the source; Friedman's 13 mentions are bibliography citations. Abstention there is correct behaviour, not a defect.
  • Registry vocabulary must match the corpus. One KC was renamed Intrinsic Information → Split Information after the corpus was found to use the latter 50 times and the former never; the unit went from 0 to 27 passages. Other registries will carry similar mismatches, and the query_formulation record in each packet makes them diagnosable rather than mysterious.
  • Parent topics are out of scope. The 22 topics are nodes whose children are all knowledge units. Decision Trees, which mixes 12 KCs with a child topic, is excluded — matching the original library exactly.
  • The sociology run is a transfer demonstration, not a head-to-head. Its hierarchy shares zero ids with the one used in the earlier sociology ablation, so the two are not comparable.
